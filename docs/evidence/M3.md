# M3: Architectural timer hardware programming

**Terms:** A system register is a named processor register accessed by CPU instructions.
A PPI is an interrupt private to one core. EL means exception level, a processor privilege
level. CVAL is an absolute compare value; TVAL is a relative timer value. See the repository
glossary for the shared vocabulary.

The verified specification records the physical and virtual timer programming paths in the pinned Linux
AArch64 driver and the public Arm Generic Timer guide. It does not establish the actual
firmware privilege state, selected boot timer, counter frequency, or successful interrupt
delivery on hardware. The result is **verified with gaps**: 38 PASS and six GAP verdicts across 35 facts and
nine independently supported sequence steps, with 35 critical second readings. It is not
implementation-ready: no target OS contract, rebuilt driver, or hardware result is established.

The second register extraction was completed independently before comparison with reader A.
Physical register names, lack of offsets, control bits and CNTKCTL source constants agree.
Reader A excluded virtual programming; the draft independently reads and covers that path.
No actual physical boot timer choice is inferred from the source catalog.

System registers are ordinary supported facts because the current format's register payload
requires an MMIO offset. Offset/mask inventory compares those payloads to header integer
constants; it cannot inventory named CPU registers represented as ordinary facts. Accordingly
no inventory pass is claimed. Names, bit constants, access branches and sequence steps were
read directly and retained for independent review.
