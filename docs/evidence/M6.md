# M6 — conditional GPIO programming verified with gaps

## Terms

- GPIO: general-purpose input/output pin controller.
- Register version: the value Linux reads to select its register layout and access helpers.
- Write mask: upper-half bits selecting which lower-half values a GPIOv2 write updates.
- Gap: a question with no accepted supporting evidence and an explicit next-check method.

See the [spec](../../specs/rk3588-gpio.spec.yaml) and the driver-lab
[glossary](https://github.com/curtisgalloway/driver-lab/blob/main/GLOSSARY.md).

The deliverable describes the pinned Linux GPIOv2 programming model conditionally. It does
not establish that standard ROCK 5T V1.2 silicon returns a supported version ID. No driver was
rebuilt or run, no hardware was operated, and no header pin was presumed available.

| R7 surface | Verified source outcome | Limitation |
| --- | --- | --- |
| Bank map and version | Five device-tree bank declarations; exact runtime IDs and v1/v2 branch boundary | Source declarations and runtime selection are not measured silicon identity |
| Data, direction and input | Fifteen typed v2 register definitions; split write masks and bit helpers; data before output direction; direct input read | Hardware widths, reset defaults, read upper-half behavior and electrical limits remain gaps |
| Interrupts | Mask/enable initialization, type/polarity/both-edge configuration, direct status read, generic acknowledgement dispatch | Hardware clearing/race behavior and complete flow lifecycle remain gaps |
| Debounce | Divider calculation, shared maximum policy and clock-last driver order | Public callback requests one and returns unsupported; no pulse-filter guarantee |
| Prerequisites and teardown | Clock acquisition, parent pinctrl dependency, explicit error paths and bounded remove body | Clock/reset/power handoff, downstream teardown and safe pin ownership transfer remain gaps |
| Target OS | Explicit target-section gap | No OS integration delivered |

The spec contains 35 parent facts, including six gaps, 15 register definitions, five typed
sequences and 21 fields. All supported claims use source or device-tree evidence at Linux
commit `8d3ae59288f1e7d58d76558a6ee96d533bc5019f`; no confidential manual is cited.

Two independent register readings agree on all fifteen v2 offsets and the split masks,
runtime discriminator and direct-read exceptions. Linux's three recognized nonzero IDs all
normalize to its v2 helper branch. The lower halves are assembled by shifting the upper
word and ORing the lower read, without an explicit read mask. A single-pin clear emits a
write-mask bit with zero data; acknowledgement instead emits ones in selected data bits.

The installed current verification record covers all 35 parent facts: 29 PASS and six GAP,
with no FAIL, UNVERIFIABLE or ADJUDICATE verdicts. Two independent readers agree on all
35 keys; their delta rereads independently checked 19 changed parents and preserved the
other 16. Supported facts have exact citation precision. All fifteen register parents
explicitly declare that version selection qualifies their applicability.

The unchanged full pull-request gate passed: three roots and eight spec files, zero errors
and zero warnings in the verification check; pinned source resolution, Markdown and HTML
rendering, and the positive/negative license and cross-root self-tests also passed. Selected
GPIO source resolution reports 76 resolved anchors, zero skips and no findings. Final
Markdown and HTML views were inspected for the conditional identity, register map, sequence
ordering, citations, current verdicts and all six visible gaps. The local GNU temporary-file
compatibility workaround changes no check script.

Strict inventory is not a pass: the parser finds four version-ID defines, all omitted from
typed register/field coverage, while register names are absent because offsets are C struct
initializers. There are zero parser-unknown definitions, zero conflicts and zero mismatches.
Manual comparison covers all fifteen v2 initializers, eleven v1 boundary values and the
write/read expressions; the independent reading agrees. This is a recorded inventory
limitation, not an automated completeness claim.

Both independent readers initially found the same missing structured version dependency in
all fifteen register parents. The corrected spec declares that dependency, tightens the v1
and setup anchors, distinguishes the debounce clock-enable call from successful enabling,
and limits VERSION probing to discriminator and access observation. Both independent delta
rereads report those findings resolved.

Readiness is verified with gaps. Physical register version and MMIO applicability,
register semantics, clock/reset/power prerequisites, pin ownership and electrical limits,
shutdown/interrupt lifecycle, and target OS integration remain unresolved. VERSION observation
alone cannot validate programming semantics; public documentation and safe tests on explicitly
owned lines are separate prerequisites. No hardware, rebuilt-driver or OS acceptance is claimed.
