# Broadcom BCM2711: device-tree facts (GPL overlay)

Adds to the `bcm2711` spec in `hardware-specs-docs` the facts that only the Linux device trees
state. Every BCM2711 device-tree file in Linux is `GPL-2.0` only, so these facts live here. Each
`[DT]` parenthetical names the file and lines in the `linux` entry above (Linux v7.2). Interrupt
cells are the device tree's GIC cells: an SPI cell `n` is GIC interrupt ID `32 + n`, a PPI cell
`n` is ID `16 + n`, which the cross-checks against the datasheet's IDs below bear out.

## Quick-facts

- **Address translation in the tree.** The root uses two address cells and one size cell. The
  `soc` bus maps legacy `0x7E00_0000` (24 MB) to `0xFE00_0000`, `0x7C00_0000` (32 MB) to
  `0xFC00_0000`, and the ARM Local block, which the tree addresses as `0x4000_0000`, to
  `0xFF80_0000` (8 MB). Its `dma-ranges` maps bus `0xC000_0000` to physical `0x0` for 1 GB.
  The tree therefore describes Low Peripheral mode. `[DT]` (bcm2711.dtsi lines 10-11 and 34-45,
  linux), `[inference]` (premises: the tree's physical targets above; the datasheet's Low
  Peripheral mode places Main peripherals at `0x0_FC00_0000`–`0x0_FF7F_FFFF` and ARM Local at
  `0x0_FF80_0000`, as the `bcm2711` spec in hardware-specs-docs states, Addressing model;
  derivation: the targets fall in those ranges, not in the full-map ranges at `0x4_7C00_0000`
  and `0x4_C000_0000`) `TODO (verify on hardware)`: compare the live tree on a board booted
  with arm_peri_high=1.
- **GIC node.** `arm,gic-400`, `#interrupt-cells = <3>`, with distributor `0x4004_1000`
  (4 KB), CPU interface `0x4004_2000` (8 KB), virtual interface control `0x4004_4000` and virtual
  CPU interface `0x4004_6000` in the `soc` bus's ARM Local range, so `0xFF84_1000` and
  `0xFF84_2000` for the first two; its maintenance interrupt is PPI 9 (ID 25), level-high on all
  four CPUs. `[DT]` (bcm2711.dtsi lines 56-66, linux)
- **Architected timer and PMU.** `arm,armv8-timer` with PPIs 13, 14, 11 and 10 (IDs 29, 30, 27,
  26), all level-low on four CPUs; `arm,cortex-a72-pmu` on SPIs 16-19 (IDs 48-51), one per CPU.
  `[DT]` (bcm2711.dtsi lines 435-454, linux)
- **CPU nodes.** Four `arm,cortex-a72` CPUs with `reg` 0-3. For arm64 each uses
  `enable-method = "spin-table"` with `cpu-release-addr` `0xD8`, `0xE0`, `0xE8` and `0xF0`; the
  `cpus` node's `brcm,bcm2836-smp` method is for 32-bit kernels. The L1 data cache is described
  as 32 KB with 64-byte lines, the L1 instruction cache 48 KB, the shared L2 1 MB. `[DT]`
  (bcm2711.dtsi lines 456-542, linux)
- **Reserved stub page.** A `/memreserve/` covers physical `0x0`-`0xFFF`, commented as where the
  firmware's startup stubs live and the secondary CPUs spin. `[DT]` (bcm283x.dtsi lines 8-11,
  linux)
- **Memory node.** The board-level include carries `memory@0` with a zero placeholder `reg`
  (`<0 0 0>`), commented as filled in by the bootloader; the CMA pool is limited to the first 1 GB because some devices
  address only that much. `[DT]` (bcm2711-rpi.dtsi lines 6-11, linux), `[DT]` (bcm2711.dtsi
  lines 1125-1131, linux)
- **UART nodes.** UART0 `serial@7e201000` and UART2-5 at `0x7E20_1400`-`0x7E20_1A00` are
  `arm,pl011`, `arm,primecell`, `reg` size `0x200`, SPI 121 (ID 153) level-high, clocks
  `uartclk` (the CPRMAN UART clock) and `apb_pclk` (the VPU clock), and BCM2711 overrides the
  PrimeCell peripheral ID to `0x00341011`. UART2-5 are `disabled`. The mini UART
  `serial@7e215040` is `brcm,bcm2835-aux-uart` on SPI 93 (ID 125), shared with SPI1 and SPI2.
  `[DT]` (bcm283x.dtsi lines 304-312 and 385-391, linux), `[DT]` (bcm2711.dtsi lines 130-172 and
  1159-1185, linux)
- **System timer and GPIO.** `brcm,bcm2835-system-timer` at `0x7E00_3000` with
  `clock-frequency` 1 MHz, on SPIs 64-67 (IDs 96-99); GPIO `brcm,bcm2711-gpio` at `0x7E20_0000` on
  SPIs 113-116 (IDs 145-148), 58 lines. `[DT]` (bcm283x.dtsi lines 69-78 and 107-109, linux),
  `[DT]` (bcm2711.dtsi lines 655-662 and 1167-1172, linux)
- **Firmware mailbox and clocks.** The VideoCore mailbox is `brcm,bcm2835-mbox` at legacy
  `0x7E00_B880` (`0x40` bytes) on SPI 33 (ID 65). The firmware node
  `raspberrypi,bcm2835-firmware` talks through it, and its child `raspberrypi,firmware-clocks`
  provides clocks by firmware clock ID; the clock manager is `brcm,bcm2711-cprman`. `[DT]`
  (bcm283x.dtsi lines 100-105, linux), `[DT]` (bcm2835-rpi.dtsi lines 3-12, linux), `[DT]`
  (bcm2711.dtsi lines 637-639 and 1143-1145, linux)
- **EMMC2.** `brcm,bcm2711-emmc2` at `0x7E34_0000` on SPI 126 (ID 158), clocked by
  `BCM2711_CLOCK_EMMC2`, sits on its own `emmc2bus` whose `dma-ranges` the firmware edits because
  EMMC2's DMA limits differ between SoC revisions. `[DT]` (bcm2711.dtsi lines 412-433, linux)
- **GENET.** `brcm,bcm2711-genet-v5` at bus `0x7D58_0000` (64 KB) on SPIs 157 and 158 (IDs 189,
  190), with an MDIO block at `+0xE14`; the node has no `clocks` property. `[DT]` (bcm2711.dtsi
  lines 587-603, linux)
- **PCIe and USB 3.** `brcm,bcm2711-pcie` at bus `0x7D50_0000` on SPIs 147 (`pcie`) and 148
  (`msi`), legacy INTA-INTD on SPIs 143-146 (IDs 175-178); outbound window CPU `0x6_0000_0000`
  to PCI `0xF800_0000`, 64 MB; inbound `dma-ranges` capped at 3 GB, commented as a bug in the
  wrapper around the PCIe block. The `brcm,bcm2711-xhci` controller at `0x7E9C_0000` (SPI 176,
  ID 208) is `disabled` because it shares a USB PHY with the DWC2 controller and the bootloader
  chooses between them. `[DT]` (bcm2711.dtsi lines 545-618, linux)

## Gotchas

- **PCIe DMA must stay below 3 GB.** The PCIe inbound window ends at 3 GB because of the
  wrapper bug the tree notes; on boards with more RAM, buffers that PCIe bus masters reach
  need to come from below that. `[DT]` (bcm2711.dtsi lines 577-583, linux)
